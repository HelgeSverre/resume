# Follow-up bug hunt

Ten independent agents reviewed the adapters, terminal, command paths, cache,
filesystem discovery, performance and packaging. This records findings against
the current working tree, after the progressive-loading changes. The 78 existing
tests still pass. The subsequent implementation fixes the confirmed findings below. The tables
retain the original triggers as audit context; source line numbers refer to the
pre-fix snapshot. Regression coverage includes the shipped bundle and real PTY
handoff. Remaining platform/discovery limitations are in compatibility.md.
Severity below reflects practical impact rather than each hunter's initial label.
All local-history evidence is aggregate; no transcript contents are included.

## Highest priority

### High: untrusted terminal controls reach the display

`src/Tui.res:159-200` normalizes whitespace but does not remove escape sequences
from session text. A fixture title containing `ESC[2Jforged` appears unchanged in
the rendered selected row. The parent investigator reproduced this independently.
This permits clearing/spoofing the terminal; OSC sequences can also reach terminal
features. Sanitize session-derived display text at the rendering boundary while
retaining raw IDs and paths for properly quoted commands. Include titles, previews,
paths, working directories and status text. ANSI generated by the renderer itself
must remain intact.

### High: large valid Codex rollouts exceed Node's string limit

`src/adapters/Codex.res:38-39` reads an entire rollout into a single string. The
local store contains four files over 100 MB, with the largest approximately 1 GB.
A hunter reproduced `ERR_STRING_TOO_LONG` on a valid local rollout. The collector
classifies it as unreadable. An index entry can retain a metadata-poor placeholder;
unindexed sessions disappear. Stream JSONL records instead of constructing one
large string. This also provides a concrete target for the next cold-load
performance investigation.

## Lower-priority and defensive gaps

- `src/adapters/Codex.res:47-49`: the metadata-free filename fallback strips only
  part of a timestamp, producing an invalid ID for current rollout filenames.
- `src/Cache.res:89-123`: two independent writers can discard each other's fresh
  cache entries. Atomic rename protects JSON integrity, not lost cache updates.
  This is a reparsing/performance issue, not source-session data loss. Full normal
  scans often overlap enough that the impact is limited.
- `src/Cache.res:85-88`: stale entries are not pruned on an all-hit scan because
  persistence is skipped when `changed` is false.
- `src/adapters/Pool.res:8`: a valid JSON summary missing `sessionId` becomes a
  fabricated filename-based resume entry. All 35 local summaries have valid IDs;
  malformed future inputs should be skipped instead.
- `src/adapters/Antigravity.res:44`: arbitrary `.pb`/`.db` files are admitted as
  sessions without validating their structure.
- `src/Tui.res:85-87`: the color check uses stdout even when the picker runs on
  stderr, disabling color unnecessarily in the `eval` workflow.
- An empty scan now leaves an empty picker open instead of returning the former
  no-sessions message. This is a behavior decision rather than a critical failure.
- The benchmark script (now `scripts/Benchmark.res`): `firstResultMs` disappears from JSON output when there
  are no sessions; use explicit `null` and a deliberate median policy.

## Performance and release coverage

The eight-task bound applies per `mapBounded` invocation. OpenCode nests these
pools and can perform 64 message reads while other adapters also read files.
A scan-wide concurrency budget is worth benchmarking; the audit did not establish
that nesting causes the measured cold event-loop stalls.

The release bundle was manually exercised successfully. Automated tests still
run compiled `lib/` modules rather than the packed executable. Add a distribution
smoke test with a SQLite fixture to protect worker-file placement and npm package
inclusion. Keep that separate from tests of adapter logic.

Pi's installed v3 session format and the current Poolside ACP format passed the
local schema census. Their already-documented custom-location/platform gaps
remain; see [compatibility.md](compatibility.md).

Suggested implementation order: sanitize display text; stream large rollouts;
fix Gemini replay and per-input failure isolation; preserve metadata across
sources; make selection unambiguous; then improve Unicode and remaining edge
cases. Keep these fixes in focused changes with red-first fixtures.

## Implementation follow-up

The fixes introduced focused shared modules instead of a catch-all utils file:
`JsonLines` handles streamed record decoding, `AsyncPool` handles task scheduling,
`Display` handles terminal-safe Unicode text, and `Launch`/`Selection` own execution
and lookup. The full-codebase pass consolidated adapter failure boundaries and
preview clipping, kept cache persistence independent from scan cancellation, and
made display commands derive from the same argv plan used for execution.

The follow-up also fixed malformed fresh cache-lock reclamation with atomic
directory acquisition and owner tokens, avoided pruning files on permission
errors, suppressed only SQLite's runtime experimental notices, and corrected
Node's null-valued successful stdout-write callback. Healthy Node 22 SQLite scans
no longer accumulate experimental warnings.
